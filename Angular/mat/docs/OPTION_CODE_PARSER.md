# Контракт OptionCodeParser

Правила сверены 2026-09-24 со [спецификацией MOEX](https://www.moex.com/s205).
Модуль: `src/app/service/OptionCodeParser.service.ts`.

## Входные данные

- Основной формат `expirationDate` — `YYYY-MM-DD`. Для совместимости принимается
  `DD.MM.YY`, где `YY` означает 2000–2099. Поддерживаемый диапазон обоих форматов —
  2000–2099. Пробелы, время, неполные и несуществующие даты вызывают ошибку.
- `parseExpirationDate()` проверяет календарь и возвращает `Date` в UTC.
  Все календарные вычисления используют UTC; часовой пояс компьютера не влияет
  на результат. `parseShortCode()` возвращает дату в формате `YYYY-MM-DD`.
- `optionType`, `expirationType` и `settlementType` обязательны и типизированы
  строковыми объединениями. Неизвестные значения проверяются и во время выполнения.
- `assetCode` содержит два латинских символа/цифры с сохранением регистра.
  `strike` — конечное число, представимое обычной десятичной записью JavaScript;
  отрицательные, нулевые и дробные значения допустимы. Экспоненциальная запись
  отклоняется. `isWeekly` по умолчанию `false`.

## Правила кодирования

Короткий код имеет вид `C + P + K + M + Y + W`. Страйк `P` не дополняется нулями.

| Расчёты / исполнение | K короткого кода | K полного кода |
| --- | --- | --- |
| Премиальный / американский | A | P |
| Маржируемый / американский | B | M |
| Премиальный / европейский | C | P |

Маржируемый европейский опцион отклоняется как неподдерживаемая комбинация.
Январь–декабрь кодируются `A–L` для колл и `M–X` для пут.
У недельного опциона месяц, последняя цифра года и номер недели `A–E`
определяются по четвергу той же недели понедельник–воскресенье, включая переход
месяца/года. У месячного опциона используются месяц и год фактической даты.

Полный код имеет вид `C + K + DDMMYY + T + E + P` и сохраняет фактическую дату
экспирации. Для американского опциона `underlyingCode` обязателен и содержит
серию базового фьючерса, например `RTS-1.20` или `BR-7.20`: её нельзя восстановить
по дате опциона. Для европейского опциона есть встроенные соответствия
`SR/SBER`, `SP/SBERP`, `GZ/GAZP`, `Si/Si`, `Eu/Eu`, `CR/CNY`; остальные полные коды
передаются через `underlyingCode`.

## Разбор и границы ответственности

`parseShortCode(code, expirationDate)` требует фактическую дату из данных
контракта и проверяет её соответствие закодированным месяцу, году и неделе.
Короткий код не определяет десятилетие, точный день месячной экспирации,
переносы на праздники и серию базового фьючерса. Парсер не заменяет справочник
контрактов и торговый календарь. Изменение сигнатуры намеренное: прежняя
реализация выдавала предположения о дате за точные данные.

Этот модуль используется Jest-тестами. Страницы `option-details` и
`futures-details` используют отдельный `OptionCodeService` из
`OptionCodeParserService.service.ts` с другой моделью данных; его миграция
не входит в исправление пункта 2.

Проверка: `npm test -- --runInBand`. `option.test.ts` содержит фиксированные
примеры MOEX, все месяцы колл/пут, календарные границы и ошибочные входные данные.
