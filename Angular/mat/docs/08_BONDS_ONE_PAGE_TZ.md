# ТЗ: Раздел «Облигации» (1 страница, 5 вкладок) для проекта StockChart

## 1. Цель

Реализовать в текущем проекте (`StockChart` + `StockChart.Data` + `Angular/mat`) раздел «Облигации» на **одной странице** с 5 вкладками:

1. ОФЗ
2. Корпоративные
3. Валютные
4. Субфедеральные
5. Другие

Страница должна включать единый паттерн: **фильтры -> карта доходности -> таблица**, без перехода между разными route для вкладок.

## 2. Ограничения и реалии текущего проекта

### 2.1. Что уже есть в бэкенде

В `StockChart.Data` уже есть и используются:

- `BondSpec` (параметры выпуска/спецификация)
- `BondMarketSnapshots` (рыночный снэпшот)
- `BondCoupons` (график купонов)
- `MoexSecurityTypes` (справочник `securitytypes` из MOEX ISS: `id/name/title`)

Заполнение выполняется через `MoexSyncService` (MOEX ISS), в том числе:

- определение класса облигации `BondClass` через `MapBondClass`:
  - `OFZ_BOND -> ofz`
  - `CORPORATE_BOND -> corp`
  - `SUBFEDERAL_BOND | MUNICIPAL_BOND | REGIONAL_BOND -> subfed`
  - остальное -> `other`
- признак валютности: `IsForeignCurrency`
- импорт справочника типов бумаг `/iss/securitytypes.json` в таблицу `MoexSecurityTypes`

### 2.2. Что добавить следующим шагом для полной классификации

Для точного маппинга вкладок по MOEX `GROUP/TYPE` требуется добавить второй справочник:

- `securitygroups` (`/iss/securitygroups.json`) -> таблица `MoexSecurityGroups`

После этого в доменной модели облигаций использовать:

- `BondSpec.MoexGroup` (GROUP code)
- `BondSpec.MoexType` (TYPE code)
- join к справочникам для отображения человекочитаемых названий и правил фильтрации
### 2.3. Важный текущий gap

Отдельного публичного API-контроллера под витрину облигаций в `StockChart/Controllers` сейчас нет. Для реализации страницы требуется добавить новый `BondsController` + сервис выборки/фильтрации.

## 3. UX и маршрутизация (обязательно)

### 3.1. Маршрут

Один маршрут страницы:

- `/bonds`

Активная вкладка, фильтры, сортировка, пагинация и режим карты должны отражаться в query-параметрах URL.

Пример:

- `/bonds?tab=corp&yieldMin=14&yieldMax=25&durationMin=1&durationMax=4&orderBy=yieldPct&dir=desc&page=1&pageSize=50&mapMode=ytm_dur`

### 3.2. Вкладки

Вкладки рендерятся на одной странице (`mat-tab-group` или эквивалент), без переходов между разными страницами:

- `ofz`
- `corp`
- `cur`
- `subfed`
- `other`

Правила маппинга вкладок к данным:

- этап 1 (текущий, уже поддерживается):
  - `ofz`: `BondClass = ofz`
  - `corp`: `BondClass = corp` и `IsForeignCurrency != true`
  - `cur`: `IsForeignCurrency = true`
  - `subfed`: `BondClass = subfed`
  - `other`: `BondClass = other`
- этап 2 (после добавления `MoexSecurityGroups`):
  - приоритетная классификация по `MoexGroup`/`MoexType` через справочники MOEX
  - `BondClass` остается fallback для обратной совместимости

## 4. Функциональные требования страницы списка

### 4.1. Блок фильтров

Общие требования:

- Кнопки `Применить` и `Сбросить`.
- Фильтры влияют одновременно на карту и на таблицу.
- Состояние фильтров сохраняется в URL.

Базовый обязательный набор (все вкладки):

- `yieldMin/yieldMax` (доходность, %)
- `durationMin/durationMax` (дюрация, лет; при отсутствии поля дюрации в БД допускается временный fallback на proxy-метрику)
- `yearsToMaturityMin/yearsToMaturityMax`
- `rating[]` (мультиселект; если рейтинг в БД не заполнен, фильтр отключается фичефлагом)
- `couponFreq[]` (1/12, 1/4, 1/2, 1)
- `qualifiedOnly` (bool)
- `moexType[]` (мультиселект по `MoexSecurityTypes.name`, опционально в MVP, обязательно на этапе 2)

Дополнительно по вкладкам:

- `ofz`: `ofzType` (тип ОФЗ)
- `cur`: `nominalCurrency[]`, `settlementCurrency[]`, `isSubstituted`
- `corp`: флаги `isVdo`, `hasAmortization`, `isFloating`, `isPerpetual`, `taxBenefit`, `qualifiedOnly`

Примечание по реалиям: если часть признаков не приходит из MOEX/БД (например `isVdo`, `taxBenefit`, рейтинг/сектор), реализовать как:

1. nullable-поля в DTO,
2. недоступные фильтры в UI как disabled с подсказкой,
3. поэтапное включение после добавления источника данных.

### 4.2. Карта доходности

Обязательный блок между фильтрами и таблицей.

- Ось X: дюрация (или yearsToMaturity на этапе 1, если дюрация недоступна).
- Ось Y: выбранная метрика доходности.
- Режимы:
  - `yield_by_duration`
  - `coupon_yield_by_duration`
  - `ytm`
  - `coupon_yield_to_maturity`
- Поддержка zoom выделением области.
- Клик по точке подсвечивает строку таблицы (по `dictionaryId/secid`).

### 4.3. Таблица

Требования:

- Кликабельное имя облигации.
- Серверная сортировка.
- Пагинация (server-side).
- Быстрый рендер (виртуализация строк опционально).

Минимальный обязательный унифицированный набор колонок для этапа 1 (основан на текущих данных):

- `№`
- `Имя`
- `SECID`
- `ISIN`
- `Погашение`
- `Лет до погашения`
- `Доходность %` (`YieldPct`)
- `Цена %` (`PricePctOfPar`)
- `Цена (ден.)` (`PriceRub`)
- `НКД`
- `Купон`
- `Частота`
- `Дата купона`
- `Оферта`
- `Объем день`
- `Объем день, шт`
- `Режим торгов (BoardId)`

Расширенный набор smart-lab-полей добавлять по мере готовности источников (рейтинг, сектор, VDO и т.д.).

## 5. Страница карточки облигации

Маршрут:

- `/bonds/:secid` (дополнительно поддержать поиск по ISIN)

Содержимое:

- верхний summary-блок (цена, погашение, НКД, ближайший купон, доходности)
- KPI-блоки (параметры выпуска/торгов из `BondSpec` + последние значения из `BondMarketSnapshots`)
- календарь купонов из `BondCoupons`

Таблица купонов (обязательно):

- №
- Дата купона
- Купон
- Доходность купона
- % от номинала
- % от рынка

## 6. API-контракт (новый)

### 6.1. `GET /api/bonds/list`

Параметры:

- `tab`
- фильтры (min/max, multi-select, bool)
- `orderBy`, `dir`
- `page`, `pageSize`

Ответ:

- `items[]` (строки таблицы)
- `total`
- `facets` (опционально: доступные значения для фильтров)
- `facets.moexTypes[]` (из `MoexSecurityTypes`)
- `mapPoints[]` (точки для карты с теми же фильтрами)

### 6.2. `GET /api/bonds/:secid`

Ответ:

- `instrument` (карточка)
- `lastSnapshot`
- `coupons[]`

### 6.3. `GET /api/bonds/map`

Опционально как отдельный endpoint, если нужно разгрузить `/list`.

## 8. Расчеты и формулы (зафиксировать)

В проекте обязательно зафиксировать единые правила расчета:

- `yearsToMaturity = (MaturityDate - today) / 365.25`
- `couponFreq = round(365 / CouponPeriodDays)` при наличии `CouponPeriodDays`
- что считать `Доходность`: приоритет `BondMarketSnapshots.YieldPct`
- для `Duration`:
  - этап 1: nullable поле (или proxy)
  - этап 2: полноценный расчет/получение из источника

Все расчеты должны быть одинаковыми в API и UI (UI не пересчитывает бизнес-метрики, только отображает).

## 9. Нефункциональные требования

- `P95` ответа `/api/bonds/list` <= 800 мс при `pageSize=50`.
- Первая отрисовка страницы <= 2 сек при обычном соединении.
- Обновление данных: по расписанию через существующий `MoexSyncJob` (интервал 1-5 минут в торговое время).
- Корректная обработка пустых значений (`--`).

## 10. Этапность реализации

### Этап 1 (MVP)

- 1 страница, 5 вкладок.
- Базовые фильтры по тем полям, что уже есть в БД.
- Карта (минимум 1 режим + zoom).
- Таблица + сортировка + пагинация.
- Карточка облигации + купоны.
- Использовать `BondClass` + `IsForeignCurrency`; справочник `MoexSecurityTypes` доступен для отображения/фасетов.

### Этап 2

- Все 4 режима карты.
- Расширенные фильтры/фасеты (рейтинг, сектор, VDO, амортизация, флоатеры).
- Доработка дюрации и продвинутых расчетов доходности.
- Добавить и включить классификацию по `securitygroups` + `securitytypes` как основной механизм вкладок.

## 11. Критерии приемки

1. Раздел доступен по `/bonds`, в нем 5 вкладок на одной странице.
2. Переключение вкладок меняет выборку без смены страницы.
3. Фильтры применяются к карте и таблице одновременно.
4. Сортировка и фильтры отражаются в URL и восстанавливаются после refresh.
5. Клик по строке/имени открывает `/bonds/:secid`.
6. Карточка содержит ключевые поля выпуска + таблицу купонов.
7. Для пустых значений нет ошибок рендера, выводится `--`.
