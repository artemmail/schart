# Очистка HTML

Внешний HTML проходит через `SafeHtmlService` (`src/app/service/safe-html.service.ts`).
Сервис использует DOMPurify с явными списками разрешённых тегов, атрибутов и
CSS-свойств. Компоненты не вызывают `bypassSecurityTrustHtml` самостоятельно.

Для `[innerHTML]` используйте `safeHtml.sanitizeForBinding(source)`. Единственный
вызов `bypassSecurityTrustHtml` находится внутри этого метода **после** очистки.
Это сохраняет разрешённые inline-стили, MathML и SVG формул KaTeX, которые
встроенная очистка Angular удаляет. Не дописывайте HTML к результату очистки и
не передавайте его библиотекам для дальнейшего преобразования.

## Политика

- Сохраняются текстовое форматирование, списки, таблицы, ссылки и изображения.
  Скрипты, обработчики событий, формы, iframe, object, embed, style, template,
  произвольные пользовательские элементы и атрибуты удаляются.
- Для ссылок разрешены HTTP(S), относительные URL, `mailto:` и `tel:`. Для
  изображений — HTTP(S), относительные URL и base64 PNG/JPEG/GIF/WebP/AVIF.
  HTML/SVG data URL, `javascript:`, `vbscript:`, `file:` и `blob:` удаляются.
  Ссылки с `target="_blank"` получают `rel="noopener noreferrer"`.
- Inline CSS проходит дополнительный фильтр: только перечисленные в сервисе
  свойства оформления и простые значения, включая числовые RGB/HSL-цвета.
  URL, переменные, произвольные функции, `position` и `z-index` не допускаются.
  Смещения и размеры нужны для формул KaTeX. CSS разбирается браузером;
  разрешены также отдельные свойства сторон рамки, в которые он разворачивает
  сокращённую запись `border`.
- Для KaTeX разрешён ограниченный набор MathML-тегов и SVG `svg`/`path`/`line`.
  `MarkdownRendererService` очищает результат **после** KaTeX и `marked.parse`.
  KaTeX работает с `trust: false`, ограничениями размера и раскрытия макросов;
  исходный текст в обработчике ошибки экранируется.
- Новости и комментарии проходят одну политику. Комментарии остаются
  форматированными, поскольку создаются и редактируются в TinyMCE.
- Диалоги подтверждения и информации выводят сообщение обычной интерполяцией.
  Ссылка передаётся отдельным полем в `DialogService.info(message, link)`;
  её адрес проходит стандартную URL-очистку Angular.
- Таблица сезонности также проходит очистку. Её `data-year`/`data-month`
  включены в список разрешённых атрибутов для работы подсказок.
- Если DOMPurify не поддерживает окружение, сервис возвращает пустой результат.

## Проверка

`npm run test:html-safety` запускает отдельный набор Karma в ChromeHeadless.
Он проверяет XSS-примеры, URL, CSS, Markdown/KaTeX, реальные шаблоны диалогов,
новостей и комментариев, а также цвета и метаданные таблицы сезонности.
Конфигурация `tsconfig.html-safety.spec.json` изолирует этот набор от старых
spec-файлов проекта; обычный `npm test` продолжает запускать существующий Jest.

Основания политики: [DOMPurify](https://github.com/cure53/DOMPurify),
[безопасность Angular](https://angular.dev/best-practices/security),
[безопасность KaTeX](https://katex.org/docs/security) и
[документация Marked](https://marked.js.org/).
