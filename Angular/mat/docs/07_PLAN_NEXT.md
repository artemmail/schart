# 07. План работ: “пользовательские индикаторы как ATAS”

Ниже — план продолжения после v1 (SMA/Volume + панели + UI по schema) для выхода на уровень “как ATAS”.

## A) Уточнение требований (нужно утвердить)
1) Что означает “пользовательские”:
   - A1: пользователь выбирает из библиотеки готовых индикаторов и настраивает параметры
   - A2: пользователь может “собрать” индикатор из формул/источников (DSL)
   - A3: пользователь пишет код (скрипт/TS-плагин)
2) Какие источники нужны (минимум):
   - OHLC + volume (есть)
   - delta / cumDelta (есть в `ClusterData`)
   - OI / OIDelta (есть)
   - bid/ask volume (есть как `bv/sv` и производные)
3) Нужны ли индикаторные алерты/сигналы и условия.

## B) Ближайшие задачи (v1.1)
1) Источники:
   - расширить `SourceType` и `ctx.source()` источниками из `ClusterData` (delta, oi, bid/ask volume и т.д.)
2) UX:
   - показывать значения индикаторов в тултипе/хинте по текущему бару/курсору
3) Панели:
   - редактирование высоты панели в UI (и сохранение в `ChartSettings.IndicatorPanels`)
   - скрытие панели, если в ней нет видимых серий
4) Overlay:
   - опционально разрешить `Histogram` поверх цены (если нужно)

## C) Дальше (v2)
1) Визуальные режимы:
   - Area/Bands (две линии + заливка), Points, Text/Labels, Horizontal levels
2) Оптимизация расчёта:
   - SMA/EMA O(1) на бар (скользящее окно), общий “state per indicator”
   - батч-пересчёт диапазона при зуме/скролле только если нужно
3) DataWindow:
   - отдельная панель/таблица значений индикаторов на выбранном баре

## D) Пользовательские индикаторы (главная цель)
### Вариант D1: “формульный” (рекомендовано как быстрый и безопасный)
- DSL вида: `SMA(close, 20)`, `EMA(delta, 14)`, `SUM(volume, 10)`, `IF(cond, a, b)`
- Песочница без доступа к DOM/Angular
- Автогенерация `paramsSchema` для функций
- Быстрое добавление новых функций как built-ins

### Вариант D2: скриптовый
- интерпретатор (например, JS sandbox) + ограничения
- сложнее по безопасности и дебагу

### Вариант D3: TS-плагины
- сборка/подгрузка модулей (удобно девелоперам, хуже “пользователю”)

Рекомендация: начать с D1, а D2/D3 оставить как этап после стабилизации API.
